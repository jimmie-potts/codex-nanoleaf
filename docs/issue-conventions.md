# Issue conventions

Use **Epic** for a bounded outcome, **Work item** for an independently verifiable
increment, and **Bug** for a failure with reproduction and expected behavior.
Templates live in [.github/ISSUE_TEMPLATE](../.github/ISSUE_TEMPLATE).
Outcome and observable acceptance are required; other details are conditional.
Markdown templates preserve the Guide's level-two headings but cannot enforce
required fields in GitHub. Replace prompts and check the completed draft before
filing. No model choice or Execution recommendation is needed.

Size work for one operator, the selected Linux installation and its registered Nanoleaf devices. Preserve one light writer per device, task and scene state, unread evidence and manual control.
Source, installed/client and physical evidence remain distinct under the
[SDLC](sdlc.md); filing or grouping an issue authorizes none of those operations.

The Hub owns the shared [classification, native relationship, closure and Project
rules](https://github.com/jimmie-potts/agent-device-hub/blob/main/docs/issue-conventions.md).
Use `epic` for an explicit bounded parent and `idea` for an uncommitted possibility;
these labels do not change workflow, prerequisites, Phase or Commitment. Issues
stay in their source-owning repository. Use native parent/sub-issue links,
including cross-repository links; text mentions alone do not establish membership.
A standalone issue is valid. Preserve current parents and Guide metadata during
an authorized migration. Shared prerequisites keep one parent.

For portfolio use, reuse the existing B.U.N.N.Y. Project and the Hub's minimal
recipe. Add only authorized membership, leave unselected Phase/Commitment blank,
and preserve Project privacy and existing fields. Local runtime and device
acceptance remain governed by this repository.
